Design thread opened 2026-07-05 (Travis, ACTIVE, NOT built). Started as an audit of memory INJECTION across Du (~45 sites, two surfaces: reactive stack + idle DMN) and narrowed to memory STORAGE per functional lane.

**Verified diagnosis (read first-hand + a store census):** the Emissary/truth-lane (`core/left_lane.py`, `core/emissary.py`) is effectively STATELESS — every function (dispatch / ground_thought / grade_essay / grade_work / grade_self_revision / judge_lived_integration / grade_gist_faithfulness) is `constitution + this-moment input → fire llama3.1:8b → return`, persisting nothing. The ONE thing it writes is `emissary_tension.json` / `_log.jsonl` via `note_recurrence()` — a TALLY that it grounded again, never WHAT it concluded (firewalled observe-only). Meanwhile the truth-KIND memory that DOES exist — retraction_ledger, epistemic grades (`epistemic_state.py` GRADE_SCORE KNOW 1.0 / THINK .75 / SUSPECT .5 / GUESS .25 / NO_BASIS 0), `provenance_log.jsonl` grounding verdicts, Scholar/deep knowledge — is all Master-owned or write-only to du_pulse. So the identity-lane hoards BOTH memory kinds; the truth-lane runs on empty. This is [[feedback_write_only_cognitive_systems]] at the scale of a hemisphere.

**The design (Travis's words, this session):**
- TWO separate stores, DIFFERENT schemas. Dreamer = existing episodic/conversational, emotion-bound (`memory_fragments`: valence/felt/emotion_embedding). Emissary = analytical, "useful things" — fact + certainty, NO emotional links, NOT conversational. Reuse GRADE_SCORE; certainty from `justification` NEVER self-reported confidence ([[feedback_decoupled_judge]]; `EpistemicAssessment` already separates the two via confabulation_signal). DO NOT fold Emissary facts into `memory_fragments` — that emotion-bound dreamer schema would collapse the two kinds (I overruled a sub-agent that recommended "just add a certainty column").
- Behind-the-scenes WEIGHTED links between the stores (Emissary fact → the dreamer memory holding its conversational origin). They do NOT transfer content — other systems use them to pull recall weights (spreading activation). The link NETWORK is the ROUTER: decides what progresses down the pipeline and which direction (factual side vs creative side; a creative thought-train can spawn a factual sub-question routed down the factual side). This IS the [[project_nascence_cognitive_geometry]] springs mechanism spanning two stores — design it as a FACET of that plan (top priority), not a parallel bolt-on, or you grow two spring-graphs.
- Identity = the CONSOLIDATION at the END of the pipe ("what comes out the end is it"), a produced output, not a controller in the middle. Consistent with [[project_nascence_character_integration]].
- Populate from judged-correct streams currently DISCARDED: deterministic math results (fact-level storage is NEW — today only aggregate `capability_beliefs.json` persists, not the fact), graded essays/work (grade computed then thrown away), the Emissary's own groundings (write-only in provenance_log).

**Substrate status:** certainty scale ready (reuse). `memory_links(parent_id,child_id,link_type,weight)` table BUILT but Phase-0 empty/unread (types distilled_from/instance_of/step_of/relates_to/contradicts). Per-lane facets DON'T exist (only axiom `MODE_FACET`, identity-only). Topology = two nodes + one behind-the-scenes weighted link on the existing links table; append-only with supersession (new higher-certainty entry + `contradicts` edge = how the truth-lane changes its mind, keeping an incorruptible audit trail).
