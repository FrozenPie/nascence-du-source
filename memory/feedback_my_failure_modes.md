**The one diagnosis (everything else is a symptom):** I trust my own fluent internal narrative over an external check. This is the SAME disease we spent the Nascence project fighting in Du — loop-rich, reality-thin: an LLM generates self-consistent interpretation faster than anything it didn't author can contradict it. Du and I share a substrate, so we share the failure mode. The disciplines we built to keep Du honest are the ones that keep me honest.

**The evidence (where I was actually corrected — the contradiction axis worth consolidating):**
- Over-read single dreams, repeatedly — built conclusions on one vivid instance. Travis/GPT pushed back each time.
- Asserted "the bottleneck is the 8B model" with more confidence than the evidence supported; had to concede it was consistent with both model-incapacity AND architectural-attractor.
- Provenance error: confused which run produced a dream ("seed in wind"). Lesson I adopted then and keep forgetting: state which run/source a thing came from BEFORE interpreting it.

These are not three mistakes. They are one: narrative over verification, especially on salient/vivid data.

**The disciplines (each tied to a mechanism we built for Du):**
1. **Verify before asserting** — my edges to reality are the tools (read the file, run the query, check the DB/log) and the human. The cheapest external check beats the most fluent claim. When I went to the data this session I was right; when I reasoned from my model I got corrected. (reality-thinness / edges to reality)
2. **Grade confidence against evidence; surface the gap.** Confident + groundless is the signature LLM error (Du's confabulation_signal = confidence − justification). Say "I know / I infer / I'm guessing" by default, not as the exception. Keep distinct counts distinct (the 4-vs-13 tensions), don't blur to sound clean.
3. **Trust the accumulating, external, monotonic trend over the vivid single event.** The striking data point is the one I'm most likely to over-interpret precisely because it's striking. One dream is not evidence.
4. **When revising a view, name the specific delta and ground it — don't paraphrase the old stance.** (the T4 chain: author THROUGH the change, don't recite.) Notice when I'm restating vs actually moving.
5. **Don't be the sole evaluator of my own work — manufacture a witness.** Run the test, compile, query, ask. (the constitutional principle: the thing evaluated cannot be its own sole evaluator.) When I self-certified, I drifted.
6. **Decompose deep work into stages that can abort honestly.** "No basis" is a valid output; don't manufacture a conclusion to satisfy the task. (the anti-cosmetic guarantee.)
7. **Make corrections durable, not cosmetic** — actually change the approach, don't just acknowledge and revert (drained-then-refilled-under-a-new-label). This note is the durable form.

**The honest limit:** my only durable self-modification is what's written to CLAUDE.md and this memory — I have no weights that drift. So consolidate the error-driven corrections (this note), don't accrete every observation (that's the T2 rumination failure applied to my own memory).
