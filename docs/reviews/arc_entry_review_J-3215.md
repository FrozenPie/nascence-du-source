The solidify writer (`provisional_identity._solidify`) was written to change only the becoming facet, and nobody ported the arc write. The last arc ever written was 2026-06-18. [verified]
4. **No live reader exists, and no planned reader is concrete.** Every plausible reader either already failed once for a recorded reason, would re-open the recitation loop, would be a second copy of work another system does, or is an observer that fails its own calibration test (section 4).
5. Recommendation (section 5): **do not repair L4; do not edit `s_sys` now (D-0641); store the arc additively through the already-filed trace job J-3007, which already lists `arc_entry` in its row; drop `arc_entry` from stage 4 as part of the single post-D-0664 `s_sys` edit unless the trace shows value; and turn off the two non-discriminating T4 observer calls (founder call).**

## 3. Why `L4_narrative.arc_recent` stopped updating

One chain, all verified in the code above:

1. `apply_self_concept` is the only writer of `L4.arc_recent`. It is called only from `_apply_self_authoring`.
2. `_apply_self_authoring` is called only after the legacy cost gate, the echo guards and the drainage test.
3. Since the ENABLED flip (2026-06-22) the probation block at 2062 to 2106 **returns** before any of that. Its own comment says so ("ENABLED path ends here - never the legacy cost-gate commit").
4. The live commit is `provisional_identity._solidify`, which edits the facet through `identity_vault.commit` with a mutator that never touches L4.
5. So the only remaining writer is dead code unless `ENABLED` is turned off or the probation block throws.

It is a lost responsibility in a rewrite, not a bug in the arc code. The arc write belonged to the old commit moment; the new commit moment (solidify) is a different function, written 07 to 08 and never given the job. J-3252 C10 puts the same point as "Five solidifies since 06-22 wrote no arc"; the first solidify was actually 2026-08-09 (the five are 08-09, 08-17, 08-18, 08-19, 10-30; vault_log rows 2 to 6), so probations ran 7 weeks before the first one that could have written one.

## 5. Recommendation (one answer)

**Do not repair L4. Do not edit `s_sys` now. Store through J-3007. Make the drop part of the one post-D-0664 stage 4 edit.**

1. **Store, additively, at zero new code path.** J-3007 is already filed and its briefing lists "the full self_concept and arc_entry (when stage 3 ran)" in each `t4_chain_trace.jsonl` row. Do not add a second store beside the probation record: `open_probation` taking `self_image` alone is correct while no reader exists, and storing for a reader that is not named is the write-only failure.
2. **Judge on evidence, not hope.** Gate one analysis job on 60 trace rows (about 8 days after J-3007's restart at 8 candidates a day): does the arc carry anything the evidence plus delta plus self_concept do not (a held-out different-family judge, and a deterministic content-word novelty check), and does its opener template repeat? That job is spawned below. If it finds nothing, the drop goes into the single `s_sys` edit that D-0664 sequences (J-3252 section 7 step 5), so `s_sys` is edited once, as D-0604's defeater wanted.
3. **Do not drop it before that edit.** D-0641 rules no wording edits now, and removing the `arc_entry` clause is an `s_sys` wording edit. The cost of waiting is about 40 percent of one background-lane response per candidate (the prompt's own budgets are 50 to 120 words of arc against 60 to 150 of self_concept) at 8 candidates a day. Waiting is cheap and the trace will show whether it was ever worth anything.
4. **The two T4 witness calls**: ask the founder to switch off `t4_arc` and `t4_self_concept` observation (not chapters). A one-flag build, restart-gated. Founder call because the witness plan lists them as its jurisdiction.
5. **Hygiene**: label the frozen June arc where operators see it (session_digest, `/arc`, HUD "Arc:" label), so nobody reads "12 chapters" as live.

If the founder prefers "drop now": that needs an explicit exception to D-0641 and it would be the right call the moment the trace read finds nothing; it saves a small amount and loses nothing that is read today.
