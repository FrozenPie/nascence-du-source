## 3. The keep-up-to-date skill (`/plan-maintain`) — spec

**Run order, each run:**
1. **Lint conventions** (read-only, fail-loud): every plan in `docs/plans`+`staged` has a header `Status:` line using the vocabulary; flag missing `## Current State — verified YYYY-MM-DD`; flag ROADMAP links to non-plans and plans absent from ROADMAP; flag backslash/`:line`/non-backtick refs; flag memory files with underscore `name:` or `name:`≠filename; validate every `decisions.jsonl` `plan` against `collect_plans()`.
2. **`plan_index.py`** — first, because everything else imports its `collect_plans/slug_of`; it reads decisions.jsonl, writes nothing others consume.
3. **`plan_files_audit.py`** — produces file resolution used by liveness/edges.
4. **`build_edges.py`** — *rebuild from scratch* (delete store, regenerate): memory/plan/file/overlap edges. Must come before liveness and decide so it doesn't need INSERT-OR-IGNORE semantics.
5. **`plan_liveness.py`** — adds `evidence_for` on top of a fresh store.
6. **Regenerate decision edges from `decisions.jsonl`** (new harvester in build_edges or `decide.py rebuild`) — ledger is the source of truth; `awaits_decision`/`decided_by`/`ruled_in` are derived.
7. **Regenerate reports** with `datetime.now()` headers and undated filenames; delete dated predecessors; update `project_nascence_plan_index.md`; refresh counts in the four `reference_*_tool.md` files or delete them in favour of SKILL.md.
8. **Stamp nothing automatically.** "verified" means a human/agent read the evidence; the skill only reports which plans lack a stamp.

**Prerequisites to build first:** one shared `plan_tools/common.py` (ROOT, MEMORY_DIR, `load_edges/save_edges` atomic, slug normalisation `_→-`, path normalisation) imported by all six scripts; all scripts in one location (`C:\Nascence\scripts\`), SKILL.md files just call them. Without this, step 4's rebuild is unsafe.

## 4. What works

The filesystem-derived facts are right: zero false MISSING across 24 re-checked basenames, every row count and "new since" recomputed by the agents matched exactly, and the three edge writers genuinely coexist without clobbering each other. The no-defeater refusal in `decide` and plan-index's "UNKNOWN is an honest answer" stance are the correct epistemic defaults — the bugs are in parsing, not in design intent.

## 1. Shared edge store (`_memory_edges.jsonl`) — three full-rewrite writers

**Schema/key: identical by convention, not by code.** All three writers key on the same 5-tuple and emit the same 8 fields:
- `build_edges.py:68,75-82` (load key / add_edge fields)
- `plan_liveness.py:176,189-191`
- `decide.py:68,88-101`

Verified on the live store: all 1173 rows have the identical key set `(created, dst_id, dst_kind, edge_type, provenance, src_id, src_kind, weight)`. There is no shared module — each script re-implements `load`/`save` (build_edges.py:57-70,269-271; plan_liveness.py:171-176,193-195; decide.py:61-75). Any future field added by one writer is preserved by the others only because they round-trip whole dicts; a key-shape change in one would silently fork the store.

**Drop test (actually run):** backed up the store (`...\scratchpad\edges_xskill_before.jsonl`), ran `build_edges.py`, diffed by key.
- md5 before `ebae7e6a...` → after `ebae7e6a...` (byte-identical)
- evidence_for 105 → 105; awaits_decision 10 → 10; dropped 0; added 0; existing edges mutated 0.

So today, **no writer drops another's edges** — `build_edges` uses INSERT-OR-IGNORE (:76-77), `plan_liveness` update-or-add only on its own key (:184-192), `decide.sync_edges` pops only its own two keys (:85-86). The store is clean.

**Real cross-writer defects (design, not yet triggered):**
1. **Tolerance mismatch on a bad line.** `build_edges.py:64-67` skips an unparseable line *and then rewrites the file without it* (silent deletion); `decide.py:67` and `plan_liveness.py:175` crash on the same line. One corrupt line = build_edges quietly amputates it, the other two refuse to run.
2. **Line endings flip per writer.** Store is currently CRLF (decide.py:73 `open(...,"w")` on Windows without `newline=""`); build_edges.py:269 and plan_liveness.py:193 are the same pattern, so whichever wrote last sets CRLF. Not a correctness bug, but every rewrite is a full-file diff.
3. **No atomic write, no lock** in any of the three (:269, :193, :73). A crash mid-write truncates 1173 edges; nothing rebuilds decision edges from `decisions.jsonl`, and nothing rebuilds `evidence_for` without re-running plan_liveness.
4. **No retirement path.** build_edges never deletes; plan_liveness skips rows==0 (:179) so a log that later empties keeps its old weight; decide only retires its own two keys (not `ruled_in`). The store is append-only across all three, so stale nodes accumulate forever (see §2 phantoms).
5. **Provenance vocabularies differ**: build_edges cites a file/finding; plan_liveness embeds `(plan_liveness.py YYYY-MM-DD)` (:182-183); decide embeds the decision id + date (:90,95). query.py prints raw provenance with no writer tag, so the reader can't tell which script owns an edge except by edge_type.
