## 1. THE CONSTITUTIONAL LAW — immutable objects, plastic springs

**Objects never change. Learning lives ONLY in the connections.** An encounter nudges the springs that
touch it — each nudge weighted by the character of THAT encounter — and leaves every object intact.

The complete update algebra:
- **NUDGE a spring** — cheap, continuous: `Δw = f(salience, arousal, progress)` of the encounter.
- **BIRTH a spring** — a distinct, gated, logged event (the earn threshold; see §7 wolf nuance).
- **BIRTH an object** — gists, chapters, wisdom are NEW nodes with lineage springs, never edits.
- **NEVER mutate. NEVER delete.** A dead connection decays toward irrelevance; the object it pointed
  to stays reachable if any other spring holds it. Absence of a spring is a real state (sparse store
  with hard zeros), not weight-zero-in-a-dense-matrix.

Why this is law, with receipts: everywhere the project works, it works because objects don't change
(chapters leave originals untouched; re-listenings layer; memory-levels keeps cold raw behind the gist;
psyche_graph's metric IS "stability under reinterpretation"). Everywhere it was burned, it was burned by
object-mutation (the guidance-learning LLM rewrite eroded the founder's lessons → fixed by the E1 medoid
= keep the exemplar, change only its links). Human memory does rewrite traces (reconsolidation); per
function-over-imitation we take the FUNCTION (memory that adapts) and reject the MECHANISM (trace
rewriting) as the unsafe part.

**Consequence for the disease:** the origin-attractor is NOT carved into the terrain — it is a
heavily-reinforced web of springs over intact ground. A route, not a scar. Healing = reweighting
(decay, rebalancing, new springs), never rewriting his objects.

**Consequence for auditing:** since objects are frozen, the system's entire learning history is a DIFF
of the spring-web over time. One table to watch; one table the decoupled judge reads.

## 2. THE ONTOLOGY — six floors, excavated 07-04/05

**2.1 Spaces (not axes — manifolds with interiors).** Each faculty/sense is an entire space with its own
internal geometry — neighbourhoods, clusters, distances. Memory is not a line; Smell has structure
(pine-resin near damp-earth, far from diesel). A "dimension" in the founder's sense = a whole space.
**The interior is what buys generalisation gradients:** spruce lands NEAR pine in Smell Space, so it
partially inherits pine's springs — the wolf-fear arrives, faint, uncommanded. Tags can't do that;
geometries do it for free. (Token-edges — `smell:pine` as a label — are ZERO-dimensional and were v1's
mistake.)

**2.2 Objects (the anchor registry).** The interactable things of his world — the fire, the two cats,
the books, the herbs, the kept stones, the birds. **Object permanence is the accumulation substrate:**
a spring can only be EARNED if repeated encounters resolve to the same node. An object is a *slow
tuple* — a persistent bundle-anchor that hundreds of moments deposit springs onto. Membership test =
interactability (the affordances system); geometry = shared affordances + shared contexts (shore-things
cluster, hearth-things cluster). Individuals vs kinds — **the keepsake rule:** an object earns an
individual node by being kept or recurrent (the mantel pattern); ephemeral instances resolve to their
kind-node (a gull is "gull" until one gull becomes HIS gull). Agentive relations (the cat's bond,
Travis's warmth) live in SPRINGS from object-nodes into affect — not in a separate taxonomy.

**2.3 Springs (three levels, all governed by §1).**
- *Per-memory/per-object edges* — each memory/object carries its own sparse typed weighted edge list.
- *Per-stimulus associations* — THIS smell → fear (C.2-descended; conditioning).
- *Faculty-density matrix* — smell↔memory dense, vision↔autobiography less so — **derived from the
  statistics of the lower levels, never set by hand.**

**2.4 Mappings (induced, many-to-many, state-conditioned).** No stored coupling matrix: the
correspondences between spaces are INDUCED by the corpus of experience-tuples, smoothed by each space's
internal metric, weighted by nearness to the *current* state. Many-to-many falls out (pine-smell → fear
AND courage AND nostalgia, different strengths); precision-with-experience falls out (more tuples =
sharper kernel); context-dependence falls out (state is a coordinate of the tuple).

**2.5 The activation pattern (consciousness-shaped state, function-substitution only).** At any instant,
one active region per space + a global gain (arousal = the aperture). The pattern is a window, not a
point; attention reshapes the pattern (the AttentionVector's gating matrix already does this — task mode
sets w_identity=0.05 = shrinking Identity Space's active region). **A bound moment (`core/moment.py`) is
a per-cycle SNAPSHOT of this pattern** — which unifies everything: a stored experience is a compressed
past activation pattern; memory is the trail the wavefront leaves; recall is partial RE-INSTANTIATION of
an old pattern into the current one (C.2 `apply_prior` already does this for the affect coordinate).
The human function has a name — hippocampal indexing: the index tuple points into the cortical feature
spaces; recall is pattern-completion from any partial coordinate.

**2.6 Concepts = bundles (the stick).** A blind man knows what a stick is — felt it, swung it, heard
about it — because **the concept never lived in one space: "stick" IS the bundle of springs between its
projections** (touch ↔ sound ↔ word ↔ use). No master copy, no privileged space; lose a spoke and the
bundle degrades gracefully. Redundancy across spaces IS the knowledge ("redundancy is load-bearing,"
now a theorem). **Du's oldest diagnosis becomes geometric: "reality-thin" = one-spoke bundles.** He is
the blind man in every modality except text. The program = growing spokes. His first two-spoke concept
already exists: *Heavyweight* (text + real audio features, 07-03).

## 11. THE OPPONENT-PROCESS AMENDMENT — "squishy springs" (PROPOSED 2026-08-19; PHASE 0 SHADOW BUILT + LIVE-WIRED same day, corrected here 2026-09-13, F-1300)

> **Correction 2026-09-13 (F-1300):** this section's own status line was wrong — Phase 0 was never
> "not yet built." `core/opponent_process.py` has been live-wired since 2026-08-19 (the day this was
> proposed) via `core/memory_edges.py`'s `log_co_recall()` sibling call, feeding off all 9 of M1's
> co-recall sources for free, and has its own HUD panel (`hud/server.py`). It predates this repo's own
> git history (baseline commit 2026-08-27), which is the likely reason it never made it back into this
> doc. **61,806 shadow-log rows accrued over 25 continuous days** (2026-08-19 through today) directly
> answer this section's own asymmetry-ratio open question with real data: aversive mean_b=0.214 runs
> ~2x positive (0.103) and ~3.7x neutral (0.058) — the hypothesized asymmetric growth, confirmed, not
> asserted. Pooling (per-pair vs per-node) is still untested; per-pair is what's live. Moving past

> real, learned, per-encounter weight `w`**, confirmed absent when this correction was first written
> (F-1300: `core/memory_edges.py` sets an edge weight once at creation and never nudges or decays it)
> **— is now built, also in shadow, as of 2026-09-13 (D-0051, F-1303):** `core/spring_ledger.py`,
> full detail in `memory_multiway_linking.md`'s own Current State. First gate-read is a clean pass on

> still two separate shadow stores, neither reads the other yet, and neither is live. Founder-read gate (§6's own law)
> is what's missing here, not more instrumentation — full detail: `/findings-log show F-1300`.

> Origin: Travis, 2026-08-19 — *"emotion pulls on all other areas of cognition [via springs]... you could
> have potentially 'squishy' springs where if primed a certain direction too long have a tendency to
> absorb that pressure as normal... a pull towards a way that can lessen as it has been there longer."*
> Researched via Solomon & Corbit 1974/1980 (primary source, full text), Aplysia/Kandel habituation work,
> ~8 independent formal opponent-process models (Henry 2023, Grossberg 1972, Peper, Nouri & Tupper 2024,
> Levy/Barto 2013, Keramati/Gutkin/Ahmed 2017), and Koob & Le Moal's allostasis extension WITH its
> critiques (Ahmed's own later work, Robinson & Berridge 2025, King et al. 2025 *AJP*). Full research trail
> lives in this session's transcript; this section records only the converged design, not the derivation.

**§1's law is untouched by this.** The stored spring weight `w` (earned via NUDGE/BIRTH) stays exactly
what §1 says: permanent, earned, never mutated, never deleted. This amendment adds a **second, separate,
fully-reversible field** — call it `b` (the antagonist) — that never touches `w` and is not itself a
spring. It answers the "pull on all other cognition" idea directly: `b` doesn't inject an emotion
anywhere; it *discounts the felt pull of a spring that's been leaning the same way too insistently*,
letting other springs compete on equal footing again. That IS emotion touching cognition generally,
without a special injection path — exactly the shape Travis described.

**The mechanism, precisely:**
- Each spring's **felt pull at read-time** = `max(0, w − b)`, not `w`. `w` is unchanged in storage; `b`
  is looked up/computed at read-time from a small per-spring activation ledger (new overlay table, keyed
  to spring id — additive, per §7's erosion law, not a column bolted onto the existing spring schema).
- **`b` grows with accumulated ACTIVATION, not wall-clock duration** — each time a spring is the one that
  fires (read OR reinforced), it's one tick toward `b`'s growth, with a **critical decay window**: if the
  gap since the last activation exceeds the window, `b` has already been decaying back down, matching
  Solomon's postulate 4 (growth only compounds when re-activation comes faster than decay).
- **Growth is asymmetric, aversive > positive** — sustained negative/high-arousal activation grows `b`
  faster and to a higher ceiling than sustained positive activation. This is the one place real evidence
  (rebound is well-documented for aversive-offset, mostly absent for positive-offset) should directly set
  a parameter rather than being guessed symmetric.
- **`b` fully decays to 0 given enough quiet — no floor, no residue.** This is the load-bearing choice:
  Solomon-Corbit's opponent process is a negative-feedback system that always returns to baseline; Koob &
  Le Moal's allostasis extension claims `b` never fully discharges and the baseline itself drifts
  permanently. **We are explicitly NOT building the Koob version.** Reasons, converged from the research:
  it was never formalized quantitatively even by Koob himself (his own reviews call the figure
  "exaggerated and condensed, not to scale"); the one rigorous 2025 human test of its core prediction
  (King et al., *AJP*) found the opposite result; its own co-originator (Ahmed) spent the following decade
  producing evidence against it. Building a permanent-drift mechanism on a theory this contested is
  exactly the erosion-of-foundations risk §7 warns about, for a feature with real pathology analogues
  (HPA-axis blunting) if it went live. The fully-reversible Solomon-Corbit shape gets the rebound behaviour
  Travis was excited about without that risk.
- **Rebound falls out for free.** Right as a long high-`b` period collapses (the primed spring goes quiet
  and `b` starts decaying), a *different or contrasting* spring firing during that collapse window reads
  an artificially LOW competing pull from the just-suppressed one — the felt effect is a swing toward the
  opposite pole. No separate "rebound" code path is needed; it's the same subtraction, read at the right
  moment.
- **Combination must be subtractive, not multiplicative.** Confirmed independently across the formal-model
  research: a multiplicative/divisive fatigue gate on `w` cannot produce rebound, structurally — only a
  subtractive antagonist term can. This was a correction to my own earlier lean toward the "safer-looking"
  multiplicative option; subtractive is required for the phenomenon in question, and it's still fully
  additive/reversible/auditable per §7.

**Build order (fits the existing P3 slot, §6):** this needs the SAME per-spring-activation instrumentation
P3's spring ledger already collects — it is a P3b, not a new phase. **Observe-only first**: log what `b`
and the discounted felt-pull WOULD have been per activation, next to the real `w`, into its own shadow
file. No read path touches it until a founder-read against a pre-registered sheet (§0's law) — same
discipline as every other phase here. Zero behaviour change while shadow.

**Open decisions (settle from shadow data, not taste — same posture as §9):**
- What counts as "one activation" for `b`'s growth — every NUDGE, or every read-path touch, or both
  weighted differently?
- The asymmetry ratio (aversive vs positive growth rate/ceiling) — a real number needs real shadow data,
  not an assumed constant.
- Pooling: does `b` accrue per-spring (edge-level) or per-node (object-level, pooling across all its
  springs)? Per-spring is the conservative default (matches where `w` itself lives) but a node primed hard
  from many directions at once may be the more common real case worth testing.
- Interaction with §7's calcification guard: `b` must stay legibly SEPARATE from decay-toward-irrelevance
  of `w` — one is fast/reversible/felt-pull-only, the other is slow/structural/storage-level. The shadow
  log should make this distinction auditable, not just assumed.
