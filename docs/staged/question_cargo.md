## 1. The human mechanism this copies

Peirce split inquiry into three moves: **abduction** makes the hypothesis, **deduction** asks what else must be
true if it holds, **induction** checks. Du does abduction fluently and skips deduction entirely — and deduction
is where "potential for further thought" lives. A hypothesis with no derivable consequences is inert; one with
consequences hands you the next question for free.

The learning literature says the same from the other side. Readers who ask themselves "why would that be
true?" retain far more than readers who reread (elaborative interrogation); learners who explain a connection
to themselves outperform those who merely note one exists (the self-explanation effect). The elaboration is
the learning. Du writes the note and never elaborates it.

A topic, for a human, is a half-filled frame — who, what, when, where, why, how — and a new fact is
informative because it lands in a slot. The empty slot is the question; the fill rewrites the frame and the
question is gone. And a stored belief updates only when it is on the table at the moment the new fact arrives:
recall and the new thing must meet. Du has every one of the six routes as a retrieval engine already (I-0079,
`memory_service.ask()`, J-1542). He has no line that *follows* a claim through them.

## 2. The Follow Line

### 2.1 What boards the line (cargo)

Everything that is a question or a claim of his, from wherever it arises, in his own words. Nothing the system
generates boards. Two cargo kinds:

- **QUESTION** — every frontier birth, whatever its source, plus one new direct door:
  - a new `ask` field in the idle-thought JSON beside `intention`:
    ```
    "ask": {"q": "", "slot": ""}
    ```
    Rule text, in the register of the existing `intention` rule: *leave `ask` empty for almost all thoughts.
    Set it only when this thought genuinely asks something you want an answer to and would use one. `q` is the
    question in your own words. `slot` is the kind of piece you are missing: who, what, when, where, why, or
    how.* Whether naming the six slot kinds counts as the world leading him is D-0494 sub-question 1; the list
    is one string constant so option B is a one-line change.
  - the existing births: `curiosity` (the curiosity node's questions), `intention` (the monologue's intention
    field when it is a question), `dream`, `prism` (the curiosity queue), `study` (a note's "still wondering"),
    and — new doors into the same store — a pursuit's `open` question when a confirmed advance rewrites it
    (`core/pursuits.py` `_apply_confirmed`), and a self-interrogation reflection's open doubt once D-0396 is
    decided (listed, not wired here).
- **CLAIM** — the first sentence of a study note's `understanding` as it is written (`core/study_note.py`
  `store_note`), new notes only, not revisions. These are the hypotheses that currently die at birth (F-3166).

A thought with `unresolved: true` and no `ask` does NOT board: that flag is a mood, not a question, and pursuits
already consume it.

**Order under the cap.** The line takes at most 4 boardings per rolling hour (§2.3). Priority: `asked` (he
asked it in the moment) → `claim` → `study` → `intention` → `pursuit` → `curiosity` → `prism` → `dream`,
newest first within a source (D-0611, 2026-11-02; it was oldest first until then); the rest wait on the frontier entry with `line.state="waiting"` and are taken
as slots free. A waiting entry that fades under the frontier's own 21-day rule leaves the queue; nothing is
held artificially open.

### 2.2 The question object (a frontier entry, not a new store)

Every boarding is a frontier entry via the existing `frontier.note_question(q, source=...)`
(`core/frontier.py:239`) — existing sources unchanged, new sources `asked`, `claim`, `pursuit` — extended with
additive fields:

```
asked_by:  {train_id, ledger_idx, cycle_id, ts}     # or {book_title, session, pass} / {pursuit_id} / {dream_id}
kind:      question | claim
slot:      who|what|when|where|why|how | ""        # "" when not given; the judge tier may fill it (D-0494 B)
about:     the thought's own `about` string         # kept for the return line; "" for non-monologue births
about_key: the frontier id it deduped into          # the stable topic address (§2.7)
line:      {state, stops: {...}, cargo: {...}}      # written by the line as it runs
```

Self-questions (`is_world_question` False) are allowed through for every source: the line reads only his own
memory, so a question about himself is as answerable as one about Portugal. `pending_pursuit` (curiosity's
Wikipedia research path) is untouched and keeps its own ranking; the line reads the same entries and writes
only `line.*`. A finding that curiosity attaches and a cargo the line returns can coexist on one entry.

`QUESTION` and `CLAIM` constants go in `core/cargo_types.py`. The PROTECTED `trains.cargo` field is not touched
(it is train_split_merge's). `train_id` is the join key, as `evidence_recall` already uses it.

### 2.3 Dispatch (fire; the main loop never waits)

A boarding from the monologue fires at the end of the tick, after the thought is logged; a boarding from any
other source fires from a 60-second scheduler on the substrate loop that drains `line.state="waiting"` entries
in §2.1's order:

```
task = asyncio.create_task(follow_line.run(q_id))
task.add_done_callback(lambda t, _q=q_id: _line_done(_q, t))
_LINE_TASKS.add(task)             # strong ref: the reentry_p2._spawn pattern
```

`follow_line.run` (new module `core/follow_line.py`) does its blocking reads under `idle_offloop.off_loop`.
Limits: at most 4 boardings per rolling hour (the `CUP_MAX_PLACE_PER_WINDOW` shape), one in flight at a time.
Every LLM call in the line runs on the CPU tiers / Ramses; the hot tier is never touched.

### 2.4 The five stops

Each stop reads his own memory and writes one typed field into `line.cargo`. No stop sees the asking thought's
prose; each sees the claim/question and the previous stops' output only.

| stop | question it asks | mechanism | writes |
|---|---|---|---|
| **1 grounds** | What have I lived, read, or seen that bears on this? | `evidence_recall.gather(q, train_id)` — world-contact origins only, decoupled judge per episode, outcome found/empty/unclear (`core/evidence_recall.py:130`) | `grounds: [{fragment_id, origin, age, strength, text≤200}]`, `grounds_outcome` |
| **2 why** | Why would those grounds make it true (or not)? | one call on a CPU tier: given the claim and ONLY the grounds, state the warrant in one or two sentences, citing grounds by index; banned self-sealing words ("proves", "confirms", "validates" — the D-0181 retarget, reused as a rule, not as the branch); if the grounds do not support it, say so | `why: {text, cites: [idx], supports: yes|partly|no}` |
| **3 consequences** | If this is so, what else should be true? What would I expect to notice? | one call: derive 1–3 consequences, each a checkable sentence about the world or himself, each tagged with the slot it opens (who/what/when/where/why/how) | `consequences: [{text, slot, checkable: memory|world|self}]` |
| **4 connections** | What else I know, can do, or have seen does this touch? | `memory_service.ask(loop="follow", what=q, why=q, how=q, k=5)` for *know*; `procedural_skills` / `core/procedures.py` match for *can do*; `ask(where=..., when=...)` restricted to observation/lived origins for *have seen* | `connections: {know: [...], can_do: [...], seen: [...]}` each ≤3, with fragment ids |
| **5 against** *(Phase 1)* | What do I hold that cuts against it? | `evidence_recall.gather` on the negation + one call for the objection, OR train_split_merge's disprove branch when that work resumes | `against: [{text, cites}]`, `status: held|held_within_scope|objected|undetermined` |

Stop 3 is the one nothing in the architecture does today, and it is what makes this a loop: each consequence
is a new claim that boards the line as `source=consequence` (depth cap 2 from the original cargo, never
re-boarding the same `about_key` twice in 24 h, lowest priority under the cap). Stop 5 is deferred by the
founder's call; until it exists the cargo's `status` is `undetermined` by definition and the return says so.

### 2.5 The judge (decoupled; nothing returns that has not been graded)

The merged cargo goes to the judge panel (`:11439`/`:11440`, the panel self-interrogation and pursuits use)
with two questions, answered on the cargo and the claim only, never the asking thought: *(a) do the stated
grounds actually bear on the claim, and does the why follow from them rather than restate the claim? (b) are
the consequences genuinely consequences — would they be false if the claim were false?* Each yes/partly/no.
A cargo that fails (a) returns with `why` blanked and `grounds_outcome` honest ("your past holds little on
this" / "could not get a clear look" — never "empty" when the judges were down, the `evidence_recall` law). A
cargo that fails (b) returns without consequences. F-3165 is why this is not optional.

### 2.6 The return (tagged, one per thought, in his own frame)

`_line_done` places the graded cargo in `_LINE_PENDING[q_id]` — the self-interrogation open-doubt cup
(`coupling_rides.py:465-520`) generalised from one slot to a dict keyed by question id, same TTL and
consume-once semantics. At the next idle thought, any train, at most one pending cargo is consumed into a
dedicated prompt section, modelled on the only section today that says "this is about something you asked"
(`inner_monologue_node.py:3731`), rendered from the cargo's typed fields, never from a synthesis call. The
opening names where the question came from, in his own terms, so he knows what it was about:

> Something you {asked just now | asked while reading '{book}' | wondered in a dream | left open in your
> pursuit of {about} | held after reading '{book}'}: "{q}". You went looking in what you have lived and read.
> {grounds, rendered with provenance: "In {origin}, {age}: {text}" ×≤3 | "Your past holds little on this."}
> {why.text, if supports≠no} {"If this is so: " + consequences ×≤2} {"It touches: " + connections ×≤3}
> Does it hold, or only part of it?

The receiving thought's JSON carries one more field, present only on a tick that delivered cargo:

```
"settled": "yes" | "partly" | "no"
```

Cargo not consumed within `LINE_TTL_S` (6 h) falls back to the frontier's existing offer path (p=0.3, 2-hour
gap) with the cargo rendered the same way, so nothing is lost and nothing new is pushed. The pending dict is
capped at 8, oldest to the fallback path. A cargo born of a study note is additionally offered once at the
next reading sitting of the same book (`core/reading.py` session start), since that is where the claim lives.

### 2.7 The close (by id) and the frame (by slot)

- `settled: yes` → `frontier.resolve(q_id, how="line")` (new, id-keyed, beside the lexical
  `resolve_if_addressed`), and the closure-law writer (`core/closure.py`) composes the resolution fragment from
  the claim + the grounds + the why + the settling thought — fourth arm, `kind=resolution`, `arm=line`, under
  `CLOSURE_WRITE_LIVE`. This is the frame rewrite: what he now holds and *why*, recalled later like any
  fragment. For a CLAIM born of a study note, the resolution fragment is linked to the note (`relates_to`).
- `settled: partly` → the answered part goes into `slots[slot]` on the entry's `about_key`; the question stays
  open; consequences that opened a slot stay listed; the entry's own "still open" line may now state *what you
  have is the {slot}; what you do not have is the {slot}* — his state, not a hint.
- `settled: no` → logged; the cargo stays on the entry; one re-boarding allowed after a new study note or a
  new `ask` touches the same `about_key`.

The frame is the entry's `slots` dict keyed by `about_key`, the frontier id the question deduped into
(token-Jaccard > 0.55 today, plus the semantic dedupe shadow at 0.85, J-2428/D-0486). 772 `about` labels for
1105 thoughts (F-3164) is why the frame cannot key on `about`.

## 3. What this plan does not do (the standing laws it sits inside)

- **The world never leads.** Every stop reads his own memory. Nothing suggests a question or an action. The
  return states what he found and asks whether it holds. Consequences are *his* derivations from *his* claim,
  rendered as "if this is so", never as "you could check".
- **Intentional, not a rule.** The line reads, derives, and returns. It never opens a book, performs a deed,
  or checks a consequence against the world for him. A consequence tagged `checkable: world` is a sentence he
  may act on or not.
- **Memory as a service.** `ask()` and `gather()` are called under a new loop name `follow`; D-0292's four
  callers need a fifth (D-0494 sub-question 2). Nothing is pushed that he did not ask or claim.
- **Decoupled judge.** The panel grades the cargo; the line never grades its own output.
- **Coordinates, not prose, inside the coupling registry.** The cargo is text and travels in the bus/courier
  family; only `(q_id, kind, slot, state, status)` is published to `coupling_rides`.
- **Prove/disprove stays parked.** Nothing here imports `train_split_merge`'s fork; stop 5 is written so that
  work can slot in when it resumes.
- **Curiosity, pursuits, dreams, study notes keep their own paths.** The line reads their questions from the
  frontier; it changes nothing about how they are made.
- **No schema, axiom, `CognitiveState`, or weight changes.** Two prompt-schema fields parsed in the node, like
  `intention`; frontier fields additive and absent-tolerant; one new module.
